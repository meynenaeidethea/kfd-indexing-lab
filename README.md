## Основное задание

### Решение

**Файл с реализацией `selectProducts`:**

[src/main/kotlin/lab2/ProductSelection.kt](src/main/kotlin/lab2/ProductSelection.kt)

**Как работает функция и почему выбран такой способ обработки данных?**

Функция строит по товарам хэш-таблицу `productById` (идентификатор товара -> исходный объект `Product`). Это нужно для быстрого отбора и получения Product по id.  Исключения преобразуются в множество `excludedSet`. Это позволяет проверять исключения в среднем за O(1), без повторного прохода по каталогу и списку исключений для каждой рекомендации.

Затем функция один раз проходит список рекомендаций. Уже просмотренные идентификаторы запоминаются в множество `addedIds` (чтобы за O(1) проверять на повторы), а подходящие товары добавляются в `result`.

**Как сохраняются порядок рекомендаций и уникальность товаров? Как обрабатываются исключённые, недоступные и неизвестные товары?**

Рекомендации просматриваются в исходном порядке, и товары добавляются в конец результата. `addedIds.add(id)` возвращает `false` для уже вставленного идентификатора, поэтому повторы пропускаются. Несмотря на название, `addedIds` хранит все просмотренные уникальные идентификаторы, включая те, которые не попали в результат.

Id из `excludedSet` пропускаются. Если товара нет в `productById`, он также пропускается. Найденный товар добавляется только при `available = true`

### Сложность

Обозначения:

- `p` - число товаров в каталоге
- `r` - число идентификаторов в рекомендациях
- `e` - число идентификаторов в исключениях

**Время выполнения:**

Ожидаемое время - `O(p + r + e)`:

- построение `productById` требует просмотра `p` товаров - `O(p)`
- построение `excludedSet` требует просмотра `e` исключений - `O(e)`
- цикл просматривает `r` рекомендаций и для каждой выполняет ограниченное число проверок - суммарно `O(r)`

**Дополнительная память:**

Память с результатом - `O(p + e + r + min(p, r))`:

- `productById` хранит `p` записей - `O(p)`
- `excludedSet` хранит уникальные исключения, которых не больше `e`, и создаётся с вместимостью, зависящей от размера списка исключений - `O(e)`
- `addedIds` хранит уникальные просмотренные рекомендации, которых не больше `r`, - `O(r)`

`HashSet<Long>(capacity)` задаёт начальную вместимость

Память для результата: `ArrayList` получает вместимость `min(p, r)`, поэтому занимает `O(min(p, r))` памяти даже при небольшом числе найденных товаров. Самих элементов результата не больше `min(p, r)`. Новые объекты `Product` не создаются: хранятся ссылки на товары каталога. Входные списки в дополнительную память не включаются.

### Организация решения

**Файлы с реализацией и пример вызова:**

[src/main/kotlin/lab2/ProductSelector.kt](src/main/kotlin/lab2/ProductSelector.kt)

```kotlin
val keyboard = Product(1, "Keyboard", true)
val monitor = Product(3, "Monitor", true)
val selector = ProductSelector(listOf(keyboard, monitor))

val firstResult = selector.select(listOf(3L, 1L, 3L), emptyList(), limit = 1)
// [Product(3, "Monitor", true)]

val secondResult = selector.select(listOf(1L, 3L), listOf(3L), limit = 10)
// [Product(1, "Keyboard", true)]

selector.loadCatalog(listOf(Product(4, "Webcam", true)))

val thirdResult = selector.select(listOf(1L, 4L), emptyList(), limit = 10)
// [Product(4, "Webcam", true)]
```

**Что выполняется при загрузке каталога, а что — при каждом запросе? Как обеспечиваются независимость запросов и переход на новый каталог?**

При создании `ProductSelector` каталог один раз преобразуется в хэш-таблицу `productById`. Каждый запрос использует готовый индекс, создаёт свои `excludedSet`, `addedIds` и `result`, затем проходит рекомендации.

`loadCatalog` строит новую хэш-таблицу и заменяет старую. Следующие запросы используют новый каталог. Товары, отсутствующие в новом каталоге, больше не находятся, ранее возвращённые списки не изменяются.

**Когда прекращается просмотр рекомендаций? От чего зависит число просмотренных элементов?**

При `limit = 0` сразу возвращается пустой список, рекомендации не просматриваются. При положительном лимите после добавления товара проверяется размер результата. Если он равен `limit`, цикл завершается через `break`. Если подходящих товаров меньше лимита, просматриваются все рекомендации.

Число просмотренных элементов зависит от лимита и расположения подходящих товаров. Повторы, исключённые, недоступные и неизвестные id увеличивают число проверок, но не размер результата. Порядок рекомендаций сохраняется.

### Сложность

- `s` - фактическое число просмотренных рекомендаций, `0 <= s <= r`
- `c = min(p, r, limit)` - начальная вместимость результата при положительном лимите

| Этап | Время | Дополнительная память |
| --- | --- | --- |
| Подготовка каталога при создании или загрузке | Ожидаемое `O(p)` | `O(p)` для индекса |
| Один запрос при `limit > 0` | Ожидаемое `O(e + s)` | `O(e + s)` без общего индекса и результата |
| Один запрос при `limit = 0` | `O(1)` | `O(1)` |

**Обоснование оценок и память для результата:**

При подготовке каталога обрабатываются `p` товаров. Индекс занимает `O(p)` памяти и используется всеми последующими запросами, пока каталог не заменён.

При запросе построение `excludedSet` требует `O(e)` времени и памяти. Цикл обрабатывает `s` рекомендаций, а `addedIds` хранит не больше `s` уникальных просмотренных id. Начальная вместимость множества равна `c`, но оно может расти. При положительном лимите `c <= s`: либо просмотрены все `r` рекомендаций, либо найдено `limit` товаров и просмотрено не меньше `limit` элементов.

Память результата учитывается отдельно: `ArrayList` сразу выделяет `c` мест, поэтому занимает `O(c)`, даже если подходящих товаров меньше. Результат содержит ссылки на исходные объекты `Product`, новые товары не создаются. Вместе с общим индексом и результатом память составляет `O(p + e + s + c)`.

Оценки времени здесь и в основной части предполагают среднюю стоимость поиска и амортизированную стоимость вставки в хэш-таблицы `O(1)` при нормальном распределении хэшей. Добавление в `ArrayList` также имеет амортизированную стоимость `O(1)`.

| Пустой каталог и пустые рекомендации | `returnsEmptyListForEmptyCatalogOrEmptyRecommendations` |

**Как подтверждено досрочное завершение?**

В тесте `stopsReadingRecommendationsWhenLimitIsReached` каталог содержит доступные товары 1, 3 и 4 и недоступный товар 2. Рекомендации - `[99, 2, 3, 1, 4]`, исключений нет, лимит равен 1. Всего рекомендаций 5, фактически просмотрено 3: неизвестный id 99, недоступный товар 2 и подходящий товар 3. Результат явно сравнивается со списком из товара `Monitor`, а счётчик - с числом 3.

Для подсчёта используется тестовый `CountingList`, наследующий `AbstractList<Long>`. Его стандартный итератор получает элементы через `get`, который возвращает исходный id и увеличивает `viewedCount`. Подсчёт не меняет значения элементов и результат подбора. При нулевом лимите отдельный тест подтверждает 0 прочитанных элементов, а при нехватке товаров - просмотр всех 5 рекомендаций.
